# 规格与计划

配置与产物位置见 `../max-mode-cn/SKILL.md`。读取 [任务模板](assets/task-template.md)，按任务内容填写一份任务文档；复杂任务可拆成 spec、design、plan、tasks、verification，但保持相互链接和需求编号一致。

从用户原始问题、代码和证据归纳目标与非目标。行为描述应说明触发、前置状态、结果和失败处理；验收标准应能被实际检查。标明证据来源和置信度，不把猜测写成已确认事实。设备场景遵循核心流程中的场景引用。

先完成足以指导实施的规格、实现逻辑口语化说明和有依赖顺序的任务，再通过 `../speckit-superpowers-bridge/SKILL.md` 交接。用户明确要求只做设计时，到设计交付为止。范围清晰且已授权实施时，记录假设后继续，无需为每个阶段添加确认门槛。
