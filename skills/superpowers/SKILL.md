# 实现与证据排错

已有 speckit 规格时直接沿用；否则先澄清目标并形成适量计划。产物位置见 `../max-mode-cn/SKILL.md`。使用接收端实际提供的文件、shell、浏览器和计划工具，不依赖特定工具别名或子代理能力。

## 实现

读代码和邻近测试后选择最小、风格一致的改动。关键逻辑优先建立能暴露真实问题的失败检查，再修复并重跑；无可运行环境时使用可行的静态或模拟检查并标注局限。纯文档或配置文字修改使用结构、链接和实际加载检查，不强制编写无价值单元测试。

按有明确边界的任务推进，验证关键路径、失败路径和相邻影响。保留用户已有改动，不为完成流程擅自重置、提交或发布。独立检查可以并行；只有用户或适用项目规则授权时才委派子代理。

## 排错

1. 确认用户真实症状、分支、环境、复现步骤与失败判据。
2. 尽量缩小到最小复现，保留能区分原因的日志、协议、状态或时序证据。
3. 按证据列出少量可证伪假设，标明支持证据、反证和下一项检查，不为凑数量增加假设。
4. 用针对性断点、日志或回放区分假设，避免大量无目的改动。
5. 证据支持根因后修复，重跑最初失败检查和相关回归。解释相关性与根因证明的区别。

## 完成

检查实际差异与规格一致，记录验证命令、结果和未运行项。若缺少编译器、依赖、权限或设备，报告具体限制并给出剩余验证操作。不要将“未运行”写成“通过”。
