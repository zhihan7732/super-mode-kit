# 超级模式核心流程

配置和产物路径沿用 `../max-mode-cn/SKILL.md`；直接调用本技能时先读该入口并解析配置。规格流程见 `../speckit/SKILL.md`，执行交接见 `../speckit-superpowers-bridge/SKILL.md`，实现和排错见 `../superpowers/SKILL.md`。

1. 读取项目约束、目标实现、相邻实现、已有测试及用户提供的日志。区分事实、推断和未确认信息。有项目知识库时先查相关记录，再核对当前分支和代码；记录冲突证据。
2. 在用户请求的范围内形成中文规格，给出可验证验收标准和“实现逻辑口语化说明”。使用 `../speckit/assets/task-template.md` 建立任务产物。已有充分规格时补齐缺口，避免重复创建。
3. 明确设计、变更文件、任务依赖及验证方式。只询问会改变行为或安全边界且无法从上下文判断的事项；其余合理假设记录后继续。
4. 用户要求修改时按桥接流程执行小步变更；出现异常时进入 superpowers 的证据排错流程。仅诊断、咨询或评审时输出证据与建议，不擅自实施。
5. 验证原始问题、关键边界和相邻回归；按需要使用 `../gstack/SKILL.md` 做交付前 review 与 QA。没有现场条件时提供待现场验证步骤，明确尚未通过。
6. 更新任务状态和验证记录，交付变更、证据、限制与恢复方式。可复用知识先形成任务内记录，写入外部知识库需符合用户授权及相应技能规则。

涉及设备行为时读取 [设备检查项](references/equipment-checks.md)，只应用与任务相关的场景。一般软件任务无需生硬添加设备概念。流程的严谨度体现在证据和覆盖面，不要求固定数量的假设、测试或文档。
